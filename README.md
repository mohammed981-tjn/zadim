# Zadim — منصّة تجارة إلكترونية

> منصّةُ تجارةٍ متعدّدةُ القنوات، عربيةٌ أولاً، للسوق السعودي.
> **ليست موقعَ متجر** — بل واجهةُ عميل + مركزُ قيادةٍ إداري + تشغيلُ
> مستودعٍ فوق محرّكِ تجارةٍ واحد.

```
                    E-COMMERCE PLATFORM
                            │
        ┌───────────────────┼───────────────────┐
        │                   │                   │
     CUSTOMER             ADMIN            OPERATIONS
        │                   │                   │
     Storefront      Command Center        Fulfillment
        │                   │                   │
        └───────────────────┼───────────────────┘
                            │
                    Commerce Backend
                            │
  ┌──────────┬──────────┬───┴────┬──────────┬──────────┐
 Products   Orders   Inventory  Payments  Shipping  Marketing
```

## 🚦 الحالة

**المراحلُ ٠–١١ب و١٥ اجتازت بوّاباتِها** (`docs/07-roadmap.md`).
والباقي: ١٢ الولاء · ١٣ التحليلات · ١٤ الذكاء · ١٦ الإطلاق.

| | |
|---|---|
| الخلفيّة | Medusa v2.19 — ١٦ وحدةً، ٤١ مسار HTTP، ٢٠ هجرة |
| الواجهة | Next 16 · عربيةٌ وإنجليزية · RTL/LTR |
| البوّابات | **١٥ بوّابةً على قاعدةٍ حقيقية**، تُشغَّل في كل دفعة |
| النشر | Railway (خلفيّة) · Vercel (واجهة) — `docs/10-deployment.md` |

القاعدةُ الحاكمة التي بُني عليها هذا كلُّه: **المتطلبات ← النطاقات ←
الكيانات ← المخطط ← آلات الحالات ← عقود الواجهات ← الصلاحيات ← ثم
الكود.** ولا واجهةَ مستخدمٍ قبل ذلك كلّه.

والسبب ليس أكاديمياً: متجرٌ يبدأ بصفحاتٍ جميلة ثم يُكتشف أن المخزون
يصير سالباً عند التزاحم، أو أن الطلب ينتقل بين حالتين لا يجوز الانتقال
بينهما، أو أن الاسترداد لا يُسجَّل من صرفه ولا لماذا — يُعاد بناؤه من
الجذر بعد أن يكون فيه مالُ عملاء.

## البدء

```bash
# الخلفيّة
cd apps/backend && npm ci
cp .env.example .env            # واضبط DATABASE_URL على الأقل
psql "$DATABASE_URL" -c 'create schema if not exists zadim'
npx ts-node src/scripts/migrate-once.ts     # الهجرة تحت قفل — كما في الإنتاج
npm run seed
npm run dev

# الواجهة
cd apps/storefront && npm ci
cp .env.example .env.local      # NEXT_PUBLIC_MEDUSA_PK من لوحة الإدارة
npm run dev
```

و`npm run gates` في `apps/backend` يشغّل البوّاباتِ الخمسَ عشرةَ كلَّها —
وهي **تحتاج قاعدةً حقيقية**: الحرّاسُ في القاعدة لا في الكود، ومحاكاةٌ
لا تنفّذ SQL تُمرّرها كلَّها وهي معطَّلة.

## القواعد التي لا تُكسر

هذه ليست تفضيلاتٍ أسلوبية، بل شروطُ صحّةٍ في نظامٍ يحمل مال الناس:

1. **لا قاعدةَ عملٍ مبرمَجة في الكود** — لا سعرٌ ولا ضريبةٌ ولا أجرةُ
   شحنٍ ولا خصمٌ ولا عمولةٌ ولا قاعدةُ مخزون. كلُّها يضبطها المدير.
2. **لا بياناتٍ وهمية في مسارٍ حقيقي** — الميزةُ ليست مكتملةً حتى
   تكتمل واجهتُها وخادمُها وقاعدتُها والتحقّقُ ومعالجةُ الخطأ
   واختباراتُها.
3. **كلُّ عمليةٍ ماليةٍ أو حسّاسة مُسجَّلةٌ في `audit_logs`** — من،
   ومتى، وماذا كان، وماذا صار، ومن أي عنوان.
4. **المخطط يسبق الواجهة.** لا العكس.
5. **لا تُحذف ميزةٌ لأنها صعبة.** تُؤجَّل بقرارٍ مكتوبٍ أو تُبنى.
6. **العربية وRTL من اليوم الأول** — لا كطبقةِ ترجمةٍ تُضاف لاحقاً.

## البنية

```
zadim/
  docs/                    ← الوثائق الاثنتا عشرة + الأدلّة الستّة
  apps/
    backend/               ← Medusa v2 + وحداتُنا فوقه
      src/modules/         ← ١٦ وحدة: access · catalog · warehouse ·
                              checkout · orders · payments · fulfilment ·
                              returns · marketing · cms · zatca · integrity …
      src/api/             ← admin (٣٣ مساراً) · store (٨ مسارات)
      src/subscribers/     ← ما يقع مع الحدث (فاتورةُ الطلب · حذفُ المستخدم)
      src/jobs/            ← ما يقع بالوقت (تصريفُ صندوق التسويق)
      src/scripts/         ← البذورُ والبوّاباتُ الخمسَ عشرة
    storefront/            ← واجهة العميل — Next 16 · Mobile-first · ثنائيةُ اللغة
```

⚠️ ولوحةُ الإدارة ليست تطبيقاً منفصلاً: هي لوحةُ Medusa، وشاشاتُنا
تُضاف إليها من `apps/backend/src/admin/`.
