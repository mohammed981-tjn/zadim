# ٨) استراتيجية الاختبار

> بند ٥٢: ليس «الصفحة تفتح». الاختبارُ الذي يثبت أن الصفحة تُعرض لا
> يثبت شيئاً عن نظامٍ يحمل مال الناس.
>
> **والقاعدة الحاكمة**: كلُّ قاعدةِ عملٍ في هذه الوثائق لها اختبارٌ
> يثبت **أنها تُفرض**، واختبارٌ يثبت **أن كسرها يُرفض**. والثاني أهمّ
> — نجاحُ المسار السليم لا يثبت أن المسار الفاسد مسدود.

---

## ٠) الهرم

```
        ▲   E2E — مسارات المستخدم الحقيقية (قليلة، بطيئة، حاسمة)
       ███
      █████  التكامل — نطاقٌ + قاعدةٌ حقيقية (الأكثرُ قيمةً هنا)
     ███████
    █████████  الوحدة — منطقٌ خالص: حسابُ المجاميع، قواعدُ العروض
```

**⚠️ ومركزُ الثقل في الوسط لا في الأسفل.** أخطاءُ التجارة الحقيقية
تعيش في **التفاعل مع القاعدة**: التزاحم، والمعاملات، والقيود — لا في
دالّةٍ خالصة. فاختبارُ التكامل يعمل على **Postgres حقيقيّ** لا على
بديلٍ في الذاكرة. البديلُ في الذاكرة لا يملك قيوداً ولا معاملات، فيمرّ
عنده ما ترفضه القاعدة الحقيقية.

## ١) 🔴 اختبارات التزاحم — أهمُّها

### الاختبار الذي ذكرتَه: آخرُ قطعةٍ وعميلان

```
المعطى:  متغيّرٌ مخزونُه = ١ في مستودعٍ واحد
الفعل:   عميلان يحجزان في اللحظة نفسها
المتوقّع: واحدٌ ينجح · واحدٌ يُرفض · on_hand=1 reserved=1 available=0
المرفوض: available = -1  — ولو مرةً في ألف
```

**✅ مُنفَّذٌ ومُثبَتٌ في المرحلة ٠**:

```
buyer-2: نجح ✅
buyer-1: رُفض ⛔
ERROR: new row for relation "inventory_levels"
       violates check constraint "reserved_within_hand"
المخزون بعد: on_hand=1 reserved=1 available=0
```

**والدرسُ في مَن رفض**: لم يرفضه شرطُ `if` في التطبيق — بل **القاعدة
نفسها**. والفرقُ جوهريّ: الشرطُ في التطبيق يقرأ ثم يقرّر ثم يكتب،
وبين القراءة والكتابة يمرّ العميلُ الثاني. **والقيدُ لا فجوةَ فيه.**

### وتوسعتُه في المرحلة ٣ — بوّابةُ عبورها

```
المعطى:  مخزونٌ = ١٠
الفعل:   ١٠٠ طلبٍ متزامن
المتوقّع: ١٠ تنجح بالضبط · ٩٠ تُرفض بـOUT_OF_STOCK · المخزون = ٠
```

**ويُشغَّل في CI في كل دفعة** لا مرةً واحدة — عطلُ التزاحم يعود مع أي
إعادةِ صياغةٍ لمسار الحجز، وهو **صامتٌ حتى الجمعة البيضاء**.

### تزاحماتٌ أخرى إلزامية

| السيناريو | المتوقّع |
|---|---|
| كوبونٌ حدُّه استخدامٌ واحد · ٥٠ نداءً متزامناً | **واحدٌ فقط ينجح** — بقيدِ تفرّدٍ في `coupon_redemptions` |
| تخفيضٌ خاطف بسقف ١٠٠ قطعة · ٥٠٠ محاولة | **١٠٠ بالضبط** — بقيد `sold_within_limit` |
| نداءُ استرداد يتكرّر بنفس `Idempotency-Key` | **يُصرف مرةً واحدة** |
| ويبهوك دفعٍ يصل مرتين | **الطلبُ يُؤكَّد مرةً واحدة** |
| شحنتان تُحصّلان نفس الدفعة | `captured ≤ authorized` **يمنع التجاوز** |

## ٢) اختبارات المال — لا هامشَ خطأ فيها

| ما يُثبَت | كيف |
|---|---|
| **المجموع يوازن دائماً** | قيد `totals_balance` — ✅ **مُثبَت**: مجموعٌ خاطئ رُفض عند الكتابة |
| **لا استردادَ فوق المحصَّل** | `refunded ≤ captured ≤ authorized` |
| **الطلبُ مُجمَّد** | غيّر سعر المنتج ⇒ **فاتورةُ أمس لم تتغيّر**. اختبارٌ صريح لا افتراض |
| **الضريبةُ بنسبتها وقتَها** | غيّر النسبة من ١٥٪ إلى ٢٠٪ ⇒ الفواتيرُ السابقة بـ١٥٪ |
| **لا كسورَ ضائعة** | خصمُ ٣٣٫٣٣٪ على ثلاثة بنود ⇒ **المجموعُ = الأصل ناقصَ الخصم بالهللة** |
| **هامشُ المساهمة** | من `unit_cost` **المُجمَّدة** لا من تكلفة اليوم |

**⚠️ ومصيدةُ التقريب تُختبَر صراحةً**: خصمٌ نسبيّ يُوزَّع على بنودٍ
عدّتُها لا تقبل القسمة يترك **هللةً** — إمّا أن تضيع فلا يوازن المجموع،
أو تُضاف مرتين. **والقاعدة**: توزيعٌ بالأكبرِ باقياً (largest remainder)،
والفرقُ يُحمَّل على أكبر بند. ويُختبَر بمبالغَ قبيحةٍ متعمَّدة.

## ٣) اختبارات آلات الحالات

**لكل انتقالٍ في [`03-state-machines.md`](03-state-machines.md)
اختباران**:

```
✅ الانتقالُ المسموح ينجح ويكتب audit_logs و outbox_events
⛔ الانتقالُ الممنوع يُرفض بـTRANSITION_NOT_ALLOWED ولا يغيّر شيئاً
```

**والممنوعاتُ التي لا يجوز أن يمرّ اختبارٌ بدونها**:

| المحاولة | المتوقّع |
|---|---|
| `cancelled → confirmed` | ⛔ الملغى لا يُحيا |
| `completed → أيّ شيء` | ⛔ نهائيّ |
| إلغاءُ طلبٍ **بعد شحن شحنة** | ⛔ الطريقُ مرتجعٌ لا إلغاء |
| `picking → packed` (تخطّي `picked`) | ⛔ |
| إتمامُ لقطٍ وبندٌ ناقص | ⛔ ولا تمرّ الشحنة صامتة |
| تحصيلٌ قبل الشحن | ⛔ |
| مرتجعٌ يعيد البضاعة إلى `on_hand` مباشرةً | ⛔ تدخل `returned` والفحصُ بشريّ |

## ٤) اختبارات الصلاحيات

**كلُّ خانةٍ في [`05-rbac-matrix.md`](05-rbac-matrix.md) لها اختبار.**
لا خانةَ بلا اختبار — والمصفوفةُ فيها سبعةُ أدوارٍ × عشراتُ العمليات،
فهذا توليدٌ آليّ من جدولٍ لا كتابةٌ يدوية.

| الحالة | المتوقّع |
|---|---|
| `support` يسترد ٤٩٩ ر.س | ✅ |
| **`support` يسترد ٥٠١ ر.س** | ⛔ `LIMIT_EXCEEDED` |
| `marketing` يعدّل سعراً | ⛔ `INSUFFICIENT_PERMISSION` |
| `product` يقرأ تقرير الهامش | ⛔ |
| `inventory` يسوّي جرداً بلا موافقة ثانية | ⛔ |
| بائعٌ يقرأ طلبَ بائعٍ آخر | ⛔ **على مستوى القاعدة لا التطبيق** |
| مفتاحُ قناةٍ مُبطَل | ⛔ |

**والاختبارُ الأخطر**: `super_admin` يغيّر دورَ نفسه ⇒ يُسجَّل في
`audit_logs` **بالقيمة قبل وبعد**. من يملك كلَّ شيء هو أوّلُ من يجب أن
يُراقَب.

## ٥) اختبارات الأمن

| ما يُختبَر |
|---|
| حقنُ SQL في كل مدخل — ولا استعلامَ يُبنى بلصق النصوص |
| XSS في وصف المنتج وتقييم العميل |
| **IDOR**: عميلٌ يطلب طلبَ عميلٍ آخر بمعرّفه ⇒ `404` لا `403` (`403` تُثبت وجودَه) |
| **ويبهوكٌ بتوقيعٍ مزوَّر ⇒ يُرفض** — وإلا زوّر أيٌّ كان دفعةً ناجحة |
| رفعُ ملفٍ تنفيذيّ بامتداد صورة |
| تحديدُ معدّل النداءات على تسجيل الدخول والكوبونات |
| ثغراتُ الاعتماديات — فحصٌ آليّ في CI |

## ٦) اختبارات العربية

**لا تُترك للفحص البصري.** ثلاثُ فئاتٍ آلية:

| الفئة | المثال |
|---|---|
| **التطبيع** | `ايفون` · `آيفون` · `أيفون` · `إيفون` ⇒ **كلُّها تجد iPhone** |
| **الاتجاه** | كلُّ شاشةٍ تُصوَّر بـ`dir=rtl` وتُقارَن — **لا عنصرَ يخرج عن الإطار** |
| **الأرقام** | العرضُ بالهندية والإدخالُ بالعربية، والمبالغُ في الفاتورة كما تشترط ZATCA |

## ٧) E2E — المسارات الحرجة

| المسار |
|---|
| زائرٌ ⇒ يتصفّح ⇒ يضيف للسلة ⇒ **يشتري ضيفاً** ⇒ يستلم تأكيداً |
| عميلٌ ⇒ كوبون ⇒ عنوانٌ وطنيّ ⇒ مدى ⇒ طلبٌ ⇒ تتبّع |
| **مستودعٌ** ⇒ قائمةُ لقط ⇒ **مسحُ باركود** ⇒ تغليف ⇒ بوليصة ⇒ شحن ⇒ **تحصيل** |
| عميلٌ ⇒ مرتجع ⇒ موافقة ⇒ استلام ⇒ فحص ⇒ **استرداد** ⇒ إشعار |
| مديرٌ ⇒ يعيد ترتيب الرئيسية ⇒ **تتغيّر بلا نشرِ كود** |

## ٨) ما لا يُختبَر — وسببُه

| لا يُختبَر | لماذا |
|---|---|
| مزوّدُ الدفع نفسه | يُحاكى بعقده. واختبارُ الاتصال الحقيقي في بيئةٍ تجريبية مرةً قبل الإطلاق |
| الناقلون | نفسه |
| **تخطيطُ الواجهة بالبكسل** | يتغيّر كل أسبوع، واختبارُه يُنتج اختباراتٍ هشّةً تُعطَّل بعد شهر — والمُختبَر **السلوكُ** لا المظهر |
| ZATCA الحقيقية | بيئتُها التجريبية قبل الإطلاق، والوحداتُ على المخرَج المتوقَّع |

## ٩) تشغيلُ فحوص المرحلة ٠

المرحلة ٠ لا كودَ فيها، لكن **مخططَها يُختبَر** — والسكربت في
[`../scripts/verify-schema.sh`](../scripts/verify-schema.sh):

```bash
./scripts/verify-schema.sh
```

يُقلع Postgres مؤقتاً، ويطبّق المخطط، ويشغّل **أربعة حرّاس**:
المخزونُ السالب · موازنةُ المجاميع · مناعةُ سجلّ التدقيق · التقييمُ
بلا شراء. **ونتيجتُه صفرٌ أو فشل** — لا تقديرَ فيها.
